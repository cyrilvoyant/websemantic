# Context

## Origin

On 2 October 2026, Nicolas Fichaux presented a demonstration in which an LLM, guided by existing ontologies, linked a vague user request to information needs, data, services and co-design workshops (Data–Information–Value framework). This study transposes that idea from data and services to **existing simulation software**: from a request to a validated model configuration, and from a model run to qualified simulated data.

## Remarks from the demonstration and how this study addresses them

| # | Remark | Treatment here |
|---|---|---|
| N1 | Explain how data become useful information for the user | Request → information need → simulator output → admitted use, each link with provenance |
| N2 | Use shared ontologies to link request, information and data | Shared W3C vocabularies (QUDT, PROV-O, SHACL, DCAT); EO taxonomies out of scope |
| N3 | Vague requests need clarifying questions | Core: non-invention and clarification |
| N4 | Distinguish satellite from administrative data | Generalised as value origin: user, transformation, documented default, accepted assumption, computed |
| N5 | Iterative reformulation | Revision history in the semantic state; stability measured |
| N6 | Metadata and DMPs to judge fitness for purpose | Model selection from descriptors and CodeMeta; JSON-LD qualification of outputs |
| N7 | How to process data (algorithms, toolboxes) | The simulator is the executable processing step |
| N8 | Bring users back to co-design workshops | Perspective; possible future evaluation |
| N9 | Incomplete metadata harvesting, connectors | Limitation; offline, versioned descriptors |
| N10 | Closed artefact without web access | Controlled sources; no free completion |

## Positioning

Primary field: engineering informatics, semantic web for scientific software, FAIR research software. Earth Intelligence is a perspective: the same contract applies to environmental models, but no Earth-observation claim is made here.
